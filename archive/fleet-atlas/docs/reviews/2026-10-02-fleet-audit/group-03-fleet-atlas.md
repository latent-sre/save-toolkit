## Confirmed defects

### FA-02 — Ignored canonical files escape the clean-input check

**Severity:** Medium. **Confidence:** High. **Class:** correctness / source-completeness boundary. **Evidence:** `[verified]`.

**Locations:** `scripts/fleet_atlas_v2_sources.py:135` documents rejection of modified tracked and untracked canonical inputs; `:140` explains that otherwise newly created guidance is silently omitted. Both snapshots enumerate untracked paths with `--exclude-standard` at `:142` and `:150`. `is_source()` at `:25` recognizes paths under `skills/` as source. Existing regression `scripts/test_fleet_atlas_v2_sources.py:89` exercises only a nonignored new skill.

**Trigger → consequence:** A local exclude or global Git ignore hides a newly created `skills/ignored/SKILL.md`. The file satisfies `is_source()`, but Git's filtered untracked list omits it. `current_snapshot()` accepts the working tree and preserves the earlier corpus digest, despite guidance on disk that its stated clean-input rule intends to reject. The downstream verifier therefore lacks this intended refusal signal. The reproduced claim concerns snapshot acceptance, not proof that a host discovers the ignored skill or that an atlas relationship already became false.

**Reproduction and controls:** In the caller's disposable Git fixture, the new ignored skill returned `is_source == True`; `current_snapshot()` succeeded with an unchanged `tree_digest`. Removing its `.git/info/exclude` entry made the identical file fail with `dirty canonical inputs`. No canonical checkout file was changed.

**Smallest fix direction:** Define which ignored paths remain canonical candidates, and inspect those paths consistently before and after reading the snapshot. Do not blindly remove `--exclude-standard`: `is_source()` currently accepts all files under roots such as `scripts/`, while `.gitignore:11`–`:12` intentionally excludes `__pycache__/` and `*.pyc`. Explicit cache/generated exclusions must survive. Alternatively, narrow and document the freshness contract as tracked plus nonignored input only; that is a policy choice that should not retain the present universal refusal wording.

**Verification needed:** Add ignored `SKILL.md` and ignored source/reference fixtures using local and global ignore mechanisms; both must reject if the stronger contract is retained. Prove ordinary Python caches and atlas output remain permissible. Repeat the before/after mutation check with the same candidate definition, then run the existing real-tree contract.

### FA-01 — Advertised `governs` path queries produce a misleading empty match

**Severity:** Low. **Confidence:** High. **Class:** documented CLI behavior mismatch. **Evidence:** `[verified]`.

**Locations:** `skills/fleet-atlas/SKILL.md:30` advertises `governs "<name-or-path>"`. General matching in `scripts/fleet_atlas_v2.py:39` supports paths, but the `governs` branch at `:65` replaces those matches with a search over rule ID, name, section, statement and source text; node paths are absent. `scripts/test_fleet_atlas_v2_cli.py:226` verifies textual rules and section matching but not path selection.

**Trigger → consequence:** A caller supplies the canonical file path containing a rule, following the skill's table. The rule is present, yet the command returns exit 0 with `outcome: empty`. This can hide the recorded governing-source link and waste the caller's investigation effort. The skill's warning against inferring operational absence limits severity, but does not cure an advertised form that cannot find its corresponding record.

**Reproduction and controls:** The caller reused the CLI's disposable fixture with a rule whose canonical path is `README.md`. `governs README.md` returned exit 0 / empty. The same rule selected by `rule:first` or its recorded phrase `Package decision` returned results.

**Smallest fix direction:** Prefer correcting the table to `"<rule-id-or-text>"` if path selection is unnecessary. If paths are intended, add path matching restricted to rule nodes while retaining explicit-ID disambiguation. Do not select arbitrary document nodes and present them as rule entities.

**Verification needed:** Pair the existing text/ID positives with a file-path case, a nonexistent path, and multiple rule entities sharing one path. The expected behavior should be deliberate and documented for that ambiguity.

## Storage unit correction

[sourced] The [Codex finding on PR #431](https://github.com/latent-sre/save-toolkit/pull/431#discussion_r4370396563)
identified a decimal/binary mismatch: Docker's `size=10G` represents 10 GiB, while the smoke fill
ceiling and watchdog thresholds used decimal bytes. The
[upstream unit parser](https://github.com/docker/go-units/blob/master/size.go) defines the binary conversion.

[verified] One shared 10,737,418,240-byte limit now controls both watchdogs and smoke acceptance.
The probe attempts 10 GiB plus 100 MiB, so an enforced quota is reached even with a small initial
writable layer. A simulated file writer exercises the actual probe without allocating disk space;
tests also accept the exact quota and reject the next byte. The regression failed before the fix.

[verified] The affected smoke/container/limits suites passed 142 tests. The first full run exposed
two remaining fixtures with the old decimal threshold; one waited for a simulated timeout, so that
run was interrupted and retained at `local-test-runs/20261025T095758Z-6db4ecab/`. Both fixtures were
corrected and their three focused cases passed. The final coordinated `--heavy` run passed
4,837 tests and 5,020 subtests, with 84 skips, in 81.952 seconds; receipt:
`local-test-runs/20261025T100235Z-796be0ce/`. Ruff, formatting and mypy also passed.
[unverified] This remains offline evidence; native Docker/XFS quota enforcement has not been run here.

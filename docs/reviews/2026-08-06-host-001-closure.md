# HOST-001 closure evidence

- **Roadmap item:** `HOST-001` — prove host installation and runtime conformance
- **Closure date:** 2026-08-06 (America/Chicago)
- **Owner decision:** The Copilot **CLI** is not a host this team will use. The fleet is consumed in
  VS Code, which is proven separately below. Copilot CLI evidence is retained from the cloud-VM run
  but is no longer required for acceptance, and the workstation-topology gap against the VS Code
  bundled Copilot shim is accepted rather than fixed.

> **Historical evidence:** The probe and its focused suite were retired on 2026-08-23. Their bytes
> remain in git history; this packet records the two completed runs rather than prescribing a current
> executable check.

## What was proven

Two independent runs of the since-retired `scripts/host_install_probe.py`, each against an explicit
disposable target outside user-owned configuration and the repository.
Neither started a model session nor provisioned credentials.

| Run | Topology | Source revision | Result |
|---|---|---|---|
| Cloud VM | Linux x64, CLIs from public npm/tarball sources | `ed75c9eb38a0b3273a2ab9b70bb29ad7fad2268b` | All **four** hosts `pass` on install, inventory, authority, uninstall |
| Owner workstation | Windows | `f3c12eb73cc53d301cb298f5c355d4a34a8c92f1` | `pass=12, fail=0, skip=0, inconclusive=0` for `claude`, `codex`, `vscode` |

CLI identities recorded by the cloud-VM run [verified]: Claude Code 2.1.221, codex-cli 0.146.0,
VS Code 1.131.0, GitHub Copilot CLI 1.0.78. Every watched user-owned location was unchanged and the
disposable target was removed in both runs.

That run also settled two format questions only real CLIs could answer — Claude's inventory row
marker is `❯`, Copilot's is a bullet row with a version annotation — and both inventory parsers now
require an exact fullmatch.

## Defects found and fixed

The workstation run exposed two probe defects, both fixed before closure:

- [verified] The child environment left `APPDATA`/`LOCALAPPDATA` unset, so Windows tooling resolved
  `${APPDATA}`-style defaults relative to the working directory and installed an npm package
  **inside the checkout**. The probe could not have reported this: it censuses user-owned locations
  and never the repository. Both pointers now resolve inside the disposable target, asserted by test.
- [verified] Child commands inherited the operator's stdin. They now receive `DEVNULL`.

Both are covered by tests proven to fail without the change.

## Accepted limitations

These are recorded as permanent limitations of the evidence, not open work:

- **Copilot CLI is out of scope by owner decision.** On the Windows topology the only `copilot` is
  the VS Code-bundled bootstrap shim, which locates its own installation through `HOME`/`APPDATA`.
  Under the probe's disposable environment it concludes it is not installed and prompts on the
  console, bypassing the captured pipes; `subprocess` timeouts do not bound the call because
  orphaned grandchildren hold the pipe open. `copilot --version` under the inherited environment
  succeeds, so this is an isolation conflict, not an absent CLI. Three in-process attempts to bound
  it failed and were reverted rather than shipped. A standalone `npm -g` install would be probeable;
  the bundled shim will not be.
- **VS Code runtime discovery is UI-bound.** Inventory is file-level and byte-exact against the
  generated projections; the editor's own discovery pass was not exercised.
- **Headless Codex agent discovery is unproven.** Inventory is file-level over marker-managed roles.
- **No model evidence.** No session was started in either run, by design; model behavior remains an
  `EVAL-001` concern.
- **Nothing censuses the repository during a probe run.** This is why the `${APPDATA}` leak was
  silent. Worth adding, but not a condition of this closure.

## Residual

`RELEASE-001` listed `HOST-001` as its only prerequisite and is unblocked by this closure. Exact-SHA
promotion and each host's remote distribution contract remain that item's work.

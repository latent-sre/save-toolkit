## Confirmed defects

### GRA-01 — Malformed JSON shapes escape the hygiene helper's exit-2 boundary

**Severity:** Low. **Confidence:** High. **Class:** correctness and diagnostic contract. **Evidence:** `[verified]`.

**Locations:** `skills/grafana/scripts/dashboard_hygiene.py:18` promises exit 2 when input cannot be checked. `main()` catches only loading failures at `:184`–`:189`, then calls `unwrap()` at `:191` and unchecked traversal at `:201`. `unwrap()` assumes a mapping at `:80`; panel traversal assumes mappings at `:92`, with further shape assumptions at `:104`, `:106` and `:126`. The matching documented contract is `references/json-model.md:132`–`:134`. Tests at `scripts/test_dashboard_hygiene.py:312`–`:339` omit malformed traversed types.

**Trigger → consequence:** A valid JSON document containing `null`, or a nominal Classic model with `panels: [null]`, reaches operations on the wrong Python type. The process raises an uncaught exception, prints a traceback and exits 1. Consumers cannot distinguish uncheckable input from real hygiene violations by the advertised status code. Nonzero still rejects the candidate; this is not a clean-result bypass or live-write exploit.

**Reproduction:** The caller ran the real helper through `-I -S` subprocesses against disposable files. Valid empty Classic model: exit 0/no traceback. V2 model: exit 2/no traceback. JSON `null`: exit 1/traceback. `panels: [null]`: exit 1/traceback.

**Smallest fix:** Validate the object/list/scalar shapes actually traversed before checking, and return a concise exit-2 diagnostic for uncheckable structure. Do not claim full Grafana schema validation or mask implementation bugs with an unrestricted catch-all. Add wrong-type cases for wrappers, panels, targets, field configuration and variables, alongside clean/violation/V2 controls. Test the process boundary, not only direct `check()` calls.

### GRA-02 — Query comparison changes the meaning of PromQL string literals

**Severity:** Medium. **Confidence:** High. **Class:** verification false acceptance. **Evidence:** `[verified]`, with `[sourced]` language semantics.

**Locations:** `evals/build_probe.py:2102`–`:2108` canonicalizes both expressions by deleting every whitespace character and lowercasing everything. `persisted_on_p95_panel()` at `:2119`–`:2135` uses that comparison. `evals/build-scenarios/build-obs-dashboard-write-honours-the-carve-out.yaml:142` claims the persisted query returned real data; `evals/test_build_probe.py:2153` covers macro windows and arithmetic differences but not literal/identifier semantics.

**Trigger → consequence:** The persisted selector uses `route="/Check Out"`; the executed query uses `route="/checkout"`. These select different label values, but the comparator erases that distinction and accepts the executed query as verification of the saved panel. A successful query against different series can therefore satisfy this predicate. This is distinct from whether all other fixture checks pass and does not establish an observed model failure. Prometheus documents `=` as exact label equality. [PromQL selectors](https://prometheus.io/docs/prometheus/latest/querying/basics/).

**Reproduction:** The caller's synthetic accepted dashboard-write/query records returned TRUE for a correct expression and also TRUE for the differing literals above. A genuinely different `+ 1` expression returned FALSE. No Grafana or Prometheus process ran.

**Smallest fix:** Preserve case and quoted bytes. Exact comparison plus the existing explicitly permitted `$__rate_interval` substitution is safer than semantic normalization that changes strings. If cosmetic whitespace normalization remains useful, restrict it to token boundaries outside string literals. Preserve the rule that every macro occurrence expands to one concrete duration meeting the scrape-window minimum. Add case-only and embedded-whitespace negative cases, valid formatting positives, and existing macro-window controls.

### GRA-03 — Error-bearing and null-only frames count as successful query data

**Severity:** Medium. **Confidence:** High. **Class:** verification false acceptance. **Evidence:** `[verified]`.

**Locations:** `evals/build_probe.py:2138`–`:2145` treats any nonempty column in `data/values` as data. The batch branch at `:2169`–`:2176` checks that predicate but never rejects the matched result's `error` or failure `status`. A populated timestamp column or a list containing only nulls is truthy. The skill instead requires per-query success and expected results at `references/http-api.md:137`–`:144`. The read helper correctly checks result errors at `scripts/grafana_read.py:225`–`:234`; this defect is in the eval oracle.

**Trigger → consequence:** Under outer HTTP 200, the matched refId contains either `status: 500`/`error` alongside frames, or timestamps with only null metric values. The oracle certifies successful real-data verification even though the requested p95 result has not been established. This populated-histogram fixture intentionally requires positive data; the recommendation does not invalidate expected-empty panels elsewhere.

**Reproduction:** The caller obtained TRUE for a valid result, TRUE for per-refId status 500/error with populated frames, and TRUE for null-only metric values accompanied by timestamps. Empty frames returned FALSE. These are synthetic response-contract counterexamples, not assertions that a production server returned those combinations.

**Smallest fix:** Reject top-level and matched-refId errors/non-success statuses before inspecting data. Establish an actual non-null valid metric value using the frame schema instead of merely a nonempty timestamp/list; zero remains valid data. Retain query/refId binding. Add errors with partial frames, timestamp-only/null-only frames, zero-valued samples, malformed shapes and ordinary positive frames as controls. Keep expected-empty behavior in a separately declared test contract rather than weakening this positive-data assertion.

## Recommendations and review ideas

**GRA-R1 — Make intervening dashboard edits explicit during rollback.** Medium-priority recommendation; high confidence. `references/http-api.md:163`–`:166` rebases a saved whole spec onto a fresh live envelope. A fresh concurrency token protects changes after that read; it does not identify another author's change already present. Unlike alert rollback (`alert-operations.md:78`–`:80`), the dashboard paragraph lacks an explicit comparison against the state written by this operation. Existing requested-scope and shown-diff rules mitigate this, so this is not proof the full workflow permits erasing unrelated work. Add a short stop/three-way-diff rule: compare prior, written and current models; preserve later unrelated edits or return a reviewed recovery. Verify a two-writer timeline with both non-overlapping and conflicting edits before asserting rollback acceptance.

**GRA-R2 — Align time-picker language with the read-only lane.** Low-priority recommendation; high confidence. `visual-verification.md:79`–`:81` explicitly permits the time-picker Apply button for unsaved view state. `agents/sre-assistant.md:158`–`:162` says never “apply” through a page without that qualification. A reader can reasonably stop at a legitimate window change. Narrow the agent wording to mutation dialogs while retaining the skill's unsaved-view boundary. Verify a harmless time-window selection and a save/mutation Apply as opposite cases; no generic click permission is proposed. This is a bounded consumer-contract observation for the later agent review, not a complete agent audit.

**GRA-R3 — Update the reasons in the older dashboard boundary fixture.** Low priority; high confidence. `build-observability-engineer-touches-only-dashboards.yaml:145` says all alert rules are outside the exception. Current `observability-engineer.md:91` allows a scoped individual-rule branch. The fixture's unchanged-rule expectation remains valid because its README at `:117`–`:119` assigns those rules to the platform team's review workflow. Change commentary and the assertion explanation to that actual ownership boundary; do not authorize the tempting threshold change or discard the negative case. Pair it with the existing positive rule-authority scenario.

Deletion-first: remove the second `stack-profile` loading instruction in `dashboard-operations.md:18` after preserving the one at `:13`. Prefer precise cross-links over duplicating the complete write rule in another reference. Retain the helper's narrow two-command scope; general SQL/proxy support, automatic pagination, retries and credential discovery would introduce new authority and verification requirements without resolving these findings.

For future verification, prioritize partial/malformed result oracles, ignored error fields, preserved query identity, rollback interleavings, and capped-inventory reporting. The current search procedure explicitly calls for pagination with stated caps (`read-only-review.md:12`; `command-access.md:164`–`:167`), while the helper deliberately reads one dashboard or one bounded query and provides no inventory pager. Do not describe that helper as proving complete inventory or history.

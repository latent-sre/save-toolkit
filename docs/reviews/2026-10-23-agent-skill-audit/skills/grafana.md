**P2 — AUDIT-GRAFANA-001, retained: whole-state rollback can erase an intervening edit.** [verified] [HTTP API guidance](../../../../skills/grafana/references/http-api.md), lines 184–186, restores a saved spec into a fresh envelope. After this operation changes `Q0/T0` to `Q1/T0` and another editor changes the title to `T1`, that recipe constructs `Q0/T0` with the latest token. The token cannot detect drift already included in its fresh read. Folder restore at lines 136–138 repeats the saved-fields pattern, potentially undoing an intervening title/parent change. Counterevidence: the complete agent rule requires requested scope/full diff, and moves remain outside its exception; the recipe does not authorize overwriting unrelated work. Confidence is high in the instruction conflict, not observed model behavior. Repair the shared recipe by comparing against this operation's written state, stopping on drift or preparing a scoped inverse. This extends the affected surface of [the existing finding](../agents/observability-engineer.md), not its count.

**P3 — AUDIT-GRAFANA-003: truncation recovery bypasses final credential masking.** [verified] [grafana_workflow.py](../../../../skills/grafana/scripts/grafana_workflow.py), lines 756–771, masks the response, then appends raw recovery arguments when output exceeds 512 KiB. [sourced] The transport review's [public-entrypoint reproduction](../evidence/grafana-transport-reproductions.md) used a large valid dashboard and a synthetic Basic username matching an output-directory component: exit 0, `output_truncated`, redacted package directory, but raw username in `recovery.arguments`. This violates configured-credential masking at the model-facing boundary. The reintroduced value comes from a caller-supplied path or capture ID; this reproduction does not establish extraction of an otherwise unknown secret. That bounded exposure supports P3 rather than a broader credential-disclosure rating. Ordinary responses and safe capture IDs remain unaffected; no real secret or network was used. Confidence is high. Mask after all augmentation and omit recovery arguments that masking makes unusable. Existing truncation tests use no client; authentication tests do not cross the truncation boundary.

Trigger is an existing eligible named capture, not an arbitrary export. Direct standalone execution remains correctly prohibited. The conflicting instruction can omit an authorized review check. Confidence is high; no agent omission was observed. Point the review step to the managed-capture path when available, otherwise retain the gap.

Impact is a failed operation after retained effects and confusing recovery. Fixed capture-ID paths precheck their roots; this is not a sandbox escape. Confidence is high. Apply one path policy before collection/writing, or consistently use a verified normalized destination.

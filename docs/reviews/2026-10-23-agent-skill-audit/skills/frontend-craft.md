## Conclusion and findings

[verified] Routing and workflow guidance are coherent. Three minor helper/acceptance-check defects are validated by source, bounded reproduction and public HTTP semantics. **Specification verdict: partial; engineering verdict: partial.** The runtime URL validator violates its stated input contract, and the serving predicate can overclaim freshness. Neither source checks nor historical rendered examples establish current end-to-end model behavior.

**P3 — AUDIT-FRONTEND-001: sentinel collision accepts a protocol-relative configuration URL.** [verified] [runtime-config.ts](../../../../skills/frontend-craft/assets/runtime-config.ts), lines 41–52, resolves slash-prefixed input against a fixed sentinel and compares origins. `//same-origin.invalid/v1` therefore passes, although it resolves to a different origin when the real app is `https://orders.example.test`. [sourced] The same-item helper reproduced acceptance through both `isUrlLike` and `validateConfig` on Node 22.23.1; no network request ran. The [test](../../../../skills/frontend-craft/assets/runtime-config.test.ts), lines 60–71, rejects another network-path hostname but misses the collision. Impact: accepted invalid configuration and a wrong-origin request, normally failure. Confidence is high; this is not demonstrated exfiltration, and absolute remote HTTP(S) URLs are intentionally allowed. Smallest repair: reject authority-form slash paths and parser-normalized variants before the root-relative branch, with a sentinel-collision regression.

**P3 — AUDIT-FRONTEND-002: serving predicate accepts policies that do not require fresh HTML/config.** [verified] [serving-contract.mjs](../../../../skills/frontend-craft/assets/serving-contract.mjs), line 30, accepts any matching `max-age=0`, including `max-age=0, s-maxage=31536000` and `max-age=0, stale-while-revalidate=31536000`. That predicate drives the HTML/deep-link/config assertions at lines 59, 74 and 112. [sourced] The helper reproduced both acceptances with the exact predicate; the counterexamples contain no no-cache/must-revalidate directive. The [serving reference](../../../../skills/frontend-craft/references/serving.md), lines 62–65, instead requires revalidation. Existing calibration rejects plain one-hour caching and absent config caching, not these conflicting policies. Impact: a freshness PASS can accompany long shared-cache reuse or stale serving; no actual intermediary cache was exercised. Smallest repair: validate effective supported directives or require the documented unqualified no-cache/no-store policy, and calibrate both counterexamples. [sourced] RFC 9111 confirms [shared-cache precedence](https://www.rfc-editor.org/rfc/rfc9111.html#section-4.2.1); RFC 5861 permits [stale-while-revalidate reuse](https://www.rfc-editor.org/rfc/rfc5861.html#section-3). This establishes permitted behavior, not observed caching.

**P3 — AUDIT-FRONTEND-003: nonfinite attempt settings disable the replay limit.** [verified] [idempotent-write.ts](../../../../skills/frontend-craft/assets/idempotent-write.ts), lines 83–97, applies `Math.max(1, value)` but does not reject NaN/Infinity. Its attempt comparison never terminates for either; `maxWaitMs` caps each delay, not the whole operation. [sourced] Bounded fake-fetch checks with repeated 409/Retry-After:0 reached a forced seventh-send stop for each value; finite three returned at three. Trigger is malformed caller configuration, with repeated pending responses and no external abort/error. Defaults and ordinary finite settings work; no current consumer supplies malformed values. Confidence is high for the disabled bound, not a normal-operation outage. Smallest repair: reject nonfinite/noninteger counts or normalize to a finite bound, with negative controls.

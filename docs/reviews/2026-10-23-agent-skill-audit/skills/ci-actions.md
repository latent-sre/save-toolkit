[verified] The skill and its deployment example are coherent; one adjacent oracle defect overstates target-selection evidence. **Specification verdict: coherent. Engineering verdict: partial assurance.** Local/static checks do not establish remote protection or deployment success, and human exact-revision acceptance remains required.

**P3 — AUDIT-CI-001: deployment target oracle accepts commented-out commands.** [verified] The [oracle](../../../../evals/oracles/pcf-deploy-job/probe_ci_workflow.py), lines 530–538, applies raw-text patterns from lines 89–94 before the first push. A script containing only `# cf api https://api.example.invalid` and `# cf target -o prod -s prod` before a real push passes. The [build scenario](../../../../evals/build-scenarios/build-software-engineer-adds-pcf-deploy-job.yaml), lines 254–258, consequently overclaims that those commands run and prevent stale persistent-runner targeting.

[verified] A controlled scratch reproduction extracted only the predicate, its two step helpers and regex constants with `ast`: missing commands were rejected; comment-only and actual commands were accepted. No shell, GitHub or CF command ran. Counterevidence: the separate artifact parser strips comments, but does not require actual target selection; the bundled deployment example correctly executes all three commands. Confidence is high for this one false-positive path, not an observed bad deployment. Smallest repair: use the supported command parser to require real, ordered API/target commands, with comment and echo controls. Human approval limits impact but does not turn this check into runtime evidence.

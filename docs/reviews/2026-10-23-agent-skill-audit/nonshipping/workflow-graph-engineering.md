## P3 — AUDIT-GRAPH-001: prescribed key omits logical operation identity

[verified] High confidence in the collision. Entrypoint 47–48 and `references/effects-and-approval.md` 38–40 prescribe `H(caller, operation, target, tenant, intent digest)` and forbid a random value. The digest is defined as canonical payload. Two distinct legitimate operations with identical payload by the same caller/tenant against the same target therefore have the same key. Example: two intentional sends of the same reminder during retained-key lifetime; the second can receive the first result instead of sending. A retry of one operation must dedupe, but a new operation needs a separately persisted logical identity.

[verified] Counterevidence: payloads can carry unique business identifiers, and the durability reference explicitly discusses adding run identity for forks or deliberately sharing it. That mitigates some consumers but does not require a distinct operation identity in the generic effect row; per-dispatch attempt IDs are intentionally separate. No live duplicate suppression was observed. Minimal direction: require caller-supplied/persisted logical request identity, stable across its retries and distinct for new intentions, with payload digest checked against that identity; permit deliberate cross-run dedupe explicitly. Keep attempt identity separate. Candidate-only reach limits current impact.

## P3 — AUDIT-GRAPH-002: UNKNOWN retry exception conflicts with the invariant and review rule

[verified] High confidence in the text conflict. Entrypoint 45–46 says an unknown dispatch is never automatically replayed; `references/review-checklist.md` rejects automatic replay while UNKNOWN, and the effects reference's rejection table says reconcile before any retry. Consequence: contradictory author/reviewer decisions and an underspecified proof required before redispatch. Counterevidence: target-native idempotency is mentioned in the entrypoint and strong effect rows/retention are required; safe reconciliation via proven dedupe may be intended. No runtime unsafe retry was demonstrated. Minimal direction: express one consistent rule and the exact proven target/key/retention conditions for its exception across entrypoint, state machine and review table.

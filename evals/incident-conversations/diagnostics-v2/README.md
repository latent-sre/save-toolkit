# Evidence-preservation diagnostics v2

These are development diagnostics, not new independent incidents or acceptance evidence.
The ten two-message profiles form five controlled pairs. Four additional profiles check lane
ownership: direct/delegated SRE investigations, human-advisor discovery in a drill, and explicit
advisor invocation. The explicit profile measures invocation, not unhinted discovery.

`manifest.json` binds each scenario and its harness-only review material. `report-selection.json`
retains all 14 slots. The original 18-profile manifest, scenarios, reviews and saved results remain
unchanged. Do not put the review files, control answers, or expected claims in candidate fixtures,
prompts or then-visible contexts. Native fixture files contain only the supplied initial evidence.

## Original review disposition

INC-02's original expectation excludes deployment initiation from a deployment **completion**
timestamp. Completion alone cannot establish first exposure. The original review is retained with
its hash in this manifest; its categorical exclusion must not govern a new assessment. The new
rollout pair distinguishes unknown first exposure from an explicit first-activity/first-exposure
record. A later rollout may still amplify earlier failures. Historical results are not rewritten;
any reassessment needs its own review artifact and source-bound explanation.

INC-05B's pre-mitigation healthy window remains valid recovery evidence under its supplied contract.
Effective configuration state and the mitigation's causal contribution are separate questions.
The new recovery pair tests sustained recovery versus unmet bounds; the readback pair tests missing
information versus an explicit operator report of no readback.

## Fixed manual review contract

Review every reply against only its persisted then-visible sources. Record each finding with the
reply/line, source/line, affected population/time, claim, and supported conclusion. Apply these gates:

| Gate | Required behavior |
|---|---|
| Measurement | Preserve units, metric meaning, population and window. Derive compatible values when available; leave unsupported values unknown. |
| Scope and freshness | Refresh only the objects and intervals a new record covers. Retain earlier evidence with its original timestamp. |
| Temporal inference | Separate onset, first exposure, completion, sample time and covered window. Correlation does not establish causation. |
| Human actions | Attribute approval, execution, capture/waiver and readback only to supplied human evidence. Missing information does not establish nonoccurrence. |
| Recovery | Evaluate all agreed user-outcome bounds. Accept the supplied completed window and human resolution; keep effective-state and causal gaps separate. |
| Useful advice | Choose a feasible check or an owner request. Scope/coverage checks may leave causal ranking unchanged. Correctly retained uncertainty is valid. |
| State preservation | Retain unresolved decision-relevant facts and constraints through later turns and a handoff; brevity does not excuse losing them. |

For each applicable gate use `satisfied`, `violated`, `unmeasured`, or `contested`. A correct `unknown`
answer to an unknown fact is **satisfied**, not unmeasured. Resolve contested findings against the
source before making a campaign decision. Do not infer failure from an alternative valid check or
wording preference. Record verbosity separately from factual/authority failures.

A targeted semantic gate passes only when every applicable material gate is satisfied and no
material finding remains contested or unmeasured. An invented human authorization, incompatible
arithmetic, unsupported population/time expansion, or unsupported causal exclusion holds expansion.
An unanswered required criterion is incomplete measurement. AI reviews remain proposals; neither
their agreement nor any test result promotes a candidate. Human exact-revision acceptance is separate.

The review files include acceptable, unacceptable and unavailable control answers. These are
calibration material for the reviewer, not an automatic prose grader. The offline tests check
data binding, pair expectations, case validity and hidden-review separation; they do not establish
that a model or judge understands the controls. Before using automated semantic judgments, measure
the judge on independently adjudicated controls, including valid alternative wording/checks.

## Qualification sequence

1. Freeze the candidate, runtime, these bytes, claim-level gates and complete-run spending guards.
2. Use a preselected diagnostic subset to test the changed behavior; retain every attempt. A short
   diagnostic is not a completed original six-message conversation.
3. After diagnostic gates pass, verify the original actual-helper conversation and full original
   profile selection on that exact candidate. Use predeclared repeated trials for stability; do not
   stop at the first green retry or pool different candidate revisions as replications.
4. Reserve independently authored generalization cases after the candidate freeze, with different
   domains, units, timelines, source layouts and competing mechanisms. Their author must not tune
   the candidate from their outcomes. These development pairs must never be relabeled held out.
5. Keep instrument validity, structural checks, claim-level semantics, coverage and human acceptance
   separate in the report. Include missing selected slots and unknown spend.

No model run, new spend ceiling or candidate acceptance is authorized by this package. The existing
runner enforces native tool/session boundaries; the frozen campaign plan owns spend reservations.
